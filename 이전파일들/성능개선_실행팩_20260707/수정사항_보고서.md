# 수정사항 보고서

## 개요

이 보고서는 `수정폴더`에 저장된 수정 코드의 변경 사항을 정리한 문서이다.
수정 목표는 논문 *Physics constrained graph neural network for real time prediction of intracranial aneurysm hemodynamics* 의 설정에 더 가깝게 맞추면서, 특히 `50-step rollout` 안정성에 영향을 크게 주는 항목들을 보수적으로 정리하는 것이었다.

이번 수정은 사용자가 요청한 다음 항목들을 중심으로 수행되었다.

1. inlet/outlet 추론 개선
2. node feature에 spatial position 반영
3. training noise 적용 방식 정리
4. boundary condition 적용의 학습/평가 일관성 강화


## 수정된 파일

- `gnn_surrogate/data.py`
- `gnn_surrogate/model.py`
- `scripts/train.py`
- `scripts/evaluate.py`
- `scripts/inspect_boundaries.py`


## 1. inlet/outlet 추론 개선

기존 코드는 속도 변화량 기반 휴리스틱으로 inlet/outlet를 추론했다.
이 방식은 재순환 영역이나 변화가 작은 내부 유동을 inlet으로 오인할 수 있어, rollout 안정성에 불리했다.

이번 수정에서는 다음 순서로 추론하도록 변경했다.

1. tetrahedra mesh에서 boundary face를 추출한다.
2. 전체 시계열에서 항상 거의 0인 속도를 갖는 노드를 wall로 복원한다.
3. wall이 아닌 boundary node를 열린 cap 후보로 모은다.
4. boundary node의 주축을 구해 양 끝 cap 두 개로 분리한다.
5. 두 cap의 평균 유속 방향을 비교해 inlet/outlet를 결정한다.
6. geometry 기반 분리가 실패하면 기존 velocity-based heuristic으로 fallback한다.

핵심 의도는 `time derivative`가 아니라 `geometry first, flow second` 방식으로 inlet/outlet를 잡는 것이다.


## 2. node feature에 spatial position 추가

논문 기준 baseline feature에는 다음이 포함된다.

- velocity
- spatial position
- timestamp
- node type

기존 구현은 `velocity + timestamp + node type`만 사용하고 있었기 때문에, spatial position 3개 성분을 다시 포함하도록 수정했다.

구현 방식은 다음과 같다.

- 각 sample의 `points`를 평균 중심화한다.
- 전체 좌표 표준편차로 나누어 정규화한다.
- 정규화된 `point_norm`을 node feature에 concatenation 한다.

이 변경으로 입력 차원이 증가하므로, 이전 checkpoint는 새 모델 구조와 바로 호환되지 않을 수 있다.


## 3. training noise 적용 방식 정리

기존 코드는 feature 생성 과정에서만 noisy current를 만들고, 실제 prediction base는 clean current를 사용하고 있었다.
이 경우 rollout robustness를 위한 noise augmentation의 의미가 약해질 수 있다.

이번 수정에서는 다음 방식으로 정리했다.

- `add_training_noise()` helper를 추가했다.
- wall node와 inlet node는 fixed boundary로 간주하고 noise를 넣지 않는다.
- interior/outlet 쪽 current velocity에만 noise를 추가한다.
- 모델은 noisy current를 입력으로 받고, 예측도 `noisy current + predicted delta` 기준으로 수행한다.

즉, 학습 시 모델이 실제로 perturbed state에서 다음 상태를 복원하도록 바뀌었다.


## 4. boundary condition 적용 일관성 강화

논문에서는 wall velocity는 0으로, inlet velocity는 ground-truth inflow 조건으로 고정한다.
기존 구현은 train/eval/rollout에서 boundary handling이 조금씩 나뉘어 있었다.

이를 정리하기 위해 공통 helper를 추가했다.

- `apply_velocity_boundary()`
- `learned_node_mask()`
- `fluid_node_mask()`

적용 방식은 다음과 같다.

- 학습 시 data loss는 `wall + inlet`을 제외한 학습 가능 노드에 대해서만 계산한다.
- physics loss도 같은 learned mask를 사용한다.
- one-step evaluation과 rollout evaluation은 boundary를 적용한 뒤 fluid domain 기준 RMSE를 계산한다.
- rollout에서 wall은 항상 0으로 유지되고, inlet은 옵션에 따라 `target_u`로 clamp된다.

이렇게 해서 학습과 평가가 같은 boundary semantics를 공유하도록 맞췄다.


## 5. 별도 점검 스크립트 추가

새로운 추론 결과를 빠르게 점검할 수 있도록 `scripts/inspect_boundaries.py`를 추가했다.

이 스크립트는 각 case에 대해 다음 정보를 출력한다.

- wall node 개수와 centroid
- inlet node 개수와 centroid
- outlet node 개수와 centroid
- `t=1` 기준 평균 속도 크기

서버에서 예시는 다음과 같다.

```bash
python scripts/inspect_boundaries.py --data-dir /path/to/coarse_dataset --max-cases 5
```


## 검증 상태

수정 후 다음 문법 검증은 통과했다.

```bash
python -m compileall gnn_surrogate scripts
```

다만 현재 로컬 환경에는 `torch`, `h5py`가 설치되어 있지 않아 다음 검증은 이 자리에서 수행하지 못했다.

- 실제 HDF5 boundary inspection 실행
- smoke training
- full training
- rollout metric 비교

따라서 실제 성능 검증은 서버 환경에서 이어서 확인해야 한다.


## 예상 영향

이번 수정으로 기대하는 효과는 다음과 같다.

- inlet/outlet 오분류 감소
- inflow context feature의 의미 회복
- training noise가 rollout robustness에 더 직접적으로 기여
- train/eval boundary handling 불일치 감소

특히 `50-step rollout` 악화의 주요 원인 후보였던 `boundary semantics mismatch`와 `inlet 추론 불안정`을 함께 줄이는 방향으로 정리되어 있다.


## 후속 확인 권장 사항

1. `inspect_boundaries.py`로 몇 개 case의 inlet/outlet 위치가 geometry 상 양 끝 cap에 놓이는지 확인
2. 새 구조로 smoke run 수행
3. `1-RMSE`와 `50-RMSE`를 이전 run과 비교
4. 필요하면 physics loss 가중치 조정을 다음 단계에서 진행
