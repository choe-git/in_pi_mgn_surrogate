# 50-RMSE 안정화 실험 가이드

## 목적

이 실행팩은 현재 50-RMSE가 약 40까지 개선된 상태에서, 논문 설정을 크게 벗어나지 않는 범위로 추가 안정화 실험을 바로 수행하기 위해 만든 파일 묶음이다.

기존 코드 구조는 유지했고, 실험은 `scripts/train.py`의 CLI 옵션으로 열어두었다. 따라서 같은 코드베이스에서 여러 후보를 순차적으로 돌려 비교할 수 있다.

## 이번에 추가한 개선축

1. `--stats-sampling uniform`

   기존 `stats-samples`는 train index 앞쪽 샘플만 사용했다. 이제 `uniform` 또는 `random`으로 전체 train trajectory에 더 넓게 퍼진 normalization statistics를 계산할 수 있다. 기본값은 `uniform`이다.

2. `--output-scale delta`

   모델은 velocity update를 예측하므로, decoder 출력 scale을 velocity field 통계가 아니라 `target_delta` 통계로 복원하는 실험을 추가했다. MeshGraphNet 계열에서 target update/acceleration을 정규화하는 방식과 잘 맞는다.

3. `--accel-mode delta`

   기존 acceleration feature는 `(u_t - u_{t-1}) / dt`라서 feature magnitude가 커질 수 있다. 논문 문장에는 velocity difference 표현도 있으므로, `delta` 모드에서 `(u_t - u_{t-1})` 자체를 정규화해 넣는 후보를 추가했다.

4. `--physics-operator gradient`

   기존 physics loss는 graph laplacian 위주 근사였다. `gradient` 모드는 논문 식처럼 local finite difference gradient를 구성하고, divergence/convection/viscosity 항을 계산한다.

5. `--selection-metric rollout`

   이전에는 best checkpoint가 1-step RMSE 기준이었다. 50-RMSE가 목표라면 validation rollout 기준 checkpoint 저장이 더 직접적이다. `--eval-rollout-steps 50`과 함께 사용한다.

6. physics weight 조정

   논문은 물리 loss scale을 초반 loss magnitude에 맞춰 조정했다고 되어 있다. 따라서 data 0.5 / physics 0.5 균등 후보와 data 0.7 / physics 0.3 후보를 모두 준비했다.

## 추천 실행 순서

### 1. boundary sanity check

```bash
python scripts/inspect_boundaries.py --data-dir /home/rintern07/04_npj/coarse_dataset --max-cases 10
```

inlet/outlet centroid가 양 끝 cap에 잡히는지 먼저 확인한다.

### 2. 가장 추천하는 In-PI-MGN 후보

```bash
bash scripts/run_stability_delta_rollout.sh
```

특징: `in-pi-mgn`, delta output scale, delta acceleration feature, gradient physics operator, rollout checkpoint selection, noise std 0.006.

### 3. data-only In-MGN 비교 후보

```bash
bash scripts/run_stability_in_mgn_data.sh
```

논문에서도 In-MGN은 long rollout이 강했다. 현재 physics loss scale이 아직 완전히 맞지 않았다면 이 후보가 더 안정적일 수 있다.

### 4. physics를 약하게 건 In-PI-MGN 후보

```bash
bash scripts/run_stability_pi_light.sh
```

physics loss가 과하면 rollout이 흔들릴 수 있어 data loss 비중을 0.7로 높인 후보이다.

### 5. noise sweep

```bash
bash scripts/run_stability_noise_sweep.sh
```

`noise-std`를 0.003, 0.006, 0.01로 바꿔 In-MGN data-only를 비교한다. 논문은 rollout robustness를 위해 training noise를 넣었다고 설명하므로, 이 sweep은 논문 취지와 잘 맞는다.

## 평가

각 run의 `best.pt`에 대해 다음처럼 평가한다.

```bash
bash scripts/evaluate_50rmse.sh /path/to/run/best.pt
```

직접 실행하려면:

```bash
python scripts/evaluate.py \
  --data-dir /home/rintern07/04_npj/coarse_dataset \
  --checkpoint /path/to/best.pt \
  --rollout-steps 50 \
  --device cuda
```

## 주의사항

- `output-scale delta`와 spatial position feature 변경 때문에 이전 checkpoint와 완전 호환되지 않을 수 있다.
- `selection-metric rollout`은 epoch마다 rollout 평가를 하므로 시간이 더 걸린다.
- 시간이 너무 오래 걸리면 `--max-test-cases 3`을 추가해 checkpoint selection용 rollout 평가를 줄이고, 마지막에는 전체 test set으로 다시 평가하면 된다.
- 논문 수치와 직접 비교하려면 test split 복구가 여전히 중요하다.
