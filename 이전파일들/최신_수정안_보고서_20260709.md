# 최신 수정안 보고서 - 50-rollout 안정성 개선 버전

작성일: 2026-07-09  
대상 코드 폴더: `GNN_surrogate 코드`  
목적: 코드를 직접 읽지 않아도, 최신 수정안에서 무엇이 바뀌었고 왜 바뀌었는지 바로 이해할 수 있도록 정리한다.

## 0. 한 줄 요약

이번 최신 수정안은 **50-step rollout에서 오차가 폭발하는 문제를 줄이기 위해**, 모델이 예측하는 값과 경계 조건, 입력 feature, physics loss, checkpoint 선택 기준을 모두 rollout 안정성 중심으로 다시 맞춘 버전이다.

핵심 변화는 다음 다섯 가지다.

1. inlet/outlet을 단순 velocity 변화량이 아니라 **mesh geometry 기반 boundary cap**으로 먼저 추론한다.
2. 모델 입력에 논문과 더 유사하게 **공간 좌표 position feature**를 추가한다.
3. 모델 출력 정규화를 velocity scale이 아니라 **delta velocity scale**로 바꿀 수 있게 했다.
4. train/evaluate/rollout에서 wall/inlet boundary condition을 **같은 helper 함수로 강제**한다.
5. `best.pt`를 1-step RMSE가 아니라 **validation 50-rollout RMSE 기준**으로 고를 수 있게 했다.

## 1. 이 수정안의 배경

기존 재현 상태에서는 1-step RMSE는 논문 수치와 비교 가능한 수준까지 접근했지만, 50-step rollout RMSE가 크게 악화되었다.

`REPRO_NOTES.md`에 기록된 첫 full run의 핵심 결과는 다음과 같았다.

| 항목 | 값 |
| --- | ---: |
| 1-RMSE | 1.5079 mm/s |
| 50-RMSE | 121.1590 mm/s |

이후 수정 후 사용자가 관찰한 결과는 50-RMSE가 약 40 수준까지 줄어든 상태다. 이는 명확한 개선이지만, 논문 목표값과는 아직 차이가 있다. 따라서 이번 수정안은 "최종 완성"이라기보다 **논문 방향을 크게 벗어나지 않으면서 rollout 안정성을 더 직접적으로 겨냥하는 실험 기반 코드**로 보는 것이 맞다.

## 2. 중요한 결론: 기존 `pt`를 이어 학습하지 않는다

사용자가 의심한 것처럼, 두 번째 run이 더 좋아졌다고 해서 현재 `train.py`가 기존 `best.pt`나 `last.pt`를 불러와 이어 학습하는 것은 아니다.

현재 `scripts/train.py`에는 다음 로직이 없다.

- `torch.load(...)`
- `model.load_state_dict(...)`
- `resume`
- 기존 checkpoint 경로를 받는 argument

현재 train 흐름은 다음과 같다.

1. `args.output_dir` 아래에 timestamp run folder를 새로 만든다.
2. `MeshGraphNet(...)`을 새로 생성한다.
3. optimizer도 새로 생성한다.
4. epoch마다 `last.pt`를 저장한다.
5. 선택 기준이 좋아진 경우 `best.pt`를 저장한다.

즉, 현재 코드는 **저장만 하고 읽지는 않는다**.

다만 같은 argument와 같은 split으로 두 번 학습해도 결과가 완전히 같을 수는 없다. 이유는 아래와 같다.

- CUDA에서 `index_add_` 기반 graph aggregation이 완전 결정론적이지 않을 수 있다.
- epoch마다 `torch.randperm(...)`으로 sample order를 섞는다.
- training noise가 `torch.randn_like(...)`로 들어간다.
- seed는 설정하지만 `torch.use_deterministic_algorithms(True)` 같은 강한 결정론 모드는 아직 켜지 않았다.

따라서 두 run이 다른 결과를 내고, 그중 하나가 더 좋은 local minimum으로 갈 수 있다. 이것은 이어 학습 증거가 아니라 **GPU 학습 비결정성과 학습 궤적 차이**로 설명되는 쪽이 더 타당하다.

## 4. 데이터/경계 조건 쪽 변경

### 4.1 기존 문제

논문은 inlet/outlet/wall 경계 조건이 명확한 상태를 전제로 한다. 하지만 현재 HDF5 dataset에는 명시적인 inlet/outlet mask가 없고, 기존 구현은 velocity 변화량 heuristic으로 inlet/outlet을 추정했다.

이 방식은 다음 문제가 있다.

- 유동 변화가 작은 outlet을 inlet처럼 잘못 볼 수 있다.
- wall mask와 실제 no-slip wall이 완전히 같지 않을 수 있다.
- rollout 중 inlet을 잘못 업데이트하면 오차가 매 step 누적된다.

### 4.2 새 방식

`gnn_surrogate/data.py`에서 inlet/outlet 추론을 다음 순서로 바꿨다.

1. tetrahedra cell에서 boundary face를 찾는다.
2. 전체 80 timestep 동안 velocity가 거의 0인 node를 wall로 복원한다.
3. wall이 아닌 boundary node를 open boundary 후보로 둔다.
4. open boundary node의 주축 principal axis를 계산한다.
5. 축 양끝의 두 cap으로 node를 나눈다.
6. 각 cap의 평균 velocity 방향을 보고 inlet/outlet을 정한다.
7. geometry 기반 추론이 실패하면 기존 velocity heuristic으로 fallback한다.

즉 최신 방식은 **geometry first, velocity second**이다.

### 4.3 추가된 mask

`GraphSample`에 `outlet_mask`가 추가되었다.

현재 mask 의미는 다음과 같다.

| mask | 의미 |
| --- | --- |
| `wall_mask` | no-slip wall, velocity를 0으로 고정해야 하는 node |
| `inlet_mask` | prescribed inflow, target inlet velocity로 clamp할 node |
| `outlet_mask` | 열린 출구 boundary, 모델이 예측할 수 있는 유체 boundary |
| `learned_node_mask` | 학습 loss 대상. 현재 `~(wall_mask | inlet_mask)` |
| `fluid_node_mask` | 평가 RMSE 대상. 현재 `~wall_mask` |

### 4.4 boundary helper

새 helper는 다음 세 개다.

- `apply_velocity_boundary(...)`
- `learned_node_mask(...)`
- `fluid_node_mask(...)`

`apply_velocity_boundary(...)`는 예측 velocity에 대해 다음을 강제한다.

1. wall velocity는 항상 0
2. inlet velocity는 기본적으로 ground-truth target inlet velocity로 clamp

이 helper를 train, validation rollout, final evaluate에서 모두 사용한다. 이 변경의 목적은 **학습 때와 평가 때 boundary 의미가 달라지는 문제를 줄이는 것**이다.

## 5. 모델 입력 feature 변경

### 5.1 기존 feature

기존 구현은 대략 다음을 사용했다.

- current velocity
- normalized time
- node type one-hot
- In-MGN/In-PI-MGN이면 acceleration과 inflow context

### 5.2 새 feature

`gnn_surrogate/model.py`에서 node feature에 **normalized spatial position**을 추가했다.

현재 기본 feature는 다음과 같다.

| feature | 차원 | 설명 |
| --- | ---: | --- |
| current velocity | 3 | velocity mean/std로 정규화 |
| position | 3 | sample 내부 좌표 평균/표준편차로 정규화 |
| time | 1 | `time_index / 79` |
| node type | 4 | interior/wall/inlet/outlet one-hot |

`in-mgn`, `in-pi-mgn` 계열에서는 여기에 다음이 추가된다.

| feature | 차원 | 설명 |
| --- | ---: | --- |
| acceleration or delta | 3 | `physical` 또는 `delta` mode |
| inflow context | 3 | inlet speed의 mean/min/max |

따라서 `in-pi-mgn` 입력 차원은 현재 `3 + 3 + 1 + 4 + 3 + 3 = 17`이다.

### 5.3 checkpoint 호환성 주의

position feature가 추가되어 node encoder input dimension이 바뀌었다. 따라서 position feature 추가 전의 오래된 checkpoint는 최신 코드와 바로 호환되지 않을 수 있다.

## 6. training noise 변경

### 6.1 기존 문제

rollout은 모델이 자기 예측값을 다음 step 입력으로 다시 넣는 구조다. 따라서 학습 때 항상 clean state만 보면, 평가 rollout에서 조금만 흔들려도 오차가 누적되기 쉽다.

### 6.2 새 방식

`add_training_noise(...)`를 통해 current velocity에 noise를 넣는다.

단, 모든 node에 noise를 넣지는 않는다.

- wall node: noise 없음
- inlet node: noise 없음
- interior/outlet node: noise 있음

그리고 예측은 다음 구조로 바뀌었다.

```text
noisy current_u -> model -> predicted delta
predicted velocity = noisy current_u + predicted delta
boundary condition 적용
```

이 구조는 rollout 중 약간 어긋난 state에서 다시 회복하는 능력을 키우기 위한 것이다.

## 7. output scale 변경

### 7.1 기존 방식

기존에는 decoder 출력 delta를 복원할 때 velocity field의 std를 사용했다.

```text
pred_delta = normalized_output * velocity_std
```

### 7.2 새 방식

`--output-scale delta`를 추가했다.

이 옵션을 쓰면 decoder output을 `target_delta = target_u - current_u`의 통계로 복원한다.

```text
pred_delta = normalized_output * delta_std + delta_mean
```

관련 파일은 다음과 같다.

- `scripts/train.py`: `--output-scale`
- `gnn_surrogate/train_utils.py`: `compute_delta_stats(...)`
- checkpoint 내부: `output_stats`
- 저장 파일: `output_stats.json`, `delta_stats.json`

### 7.3 왜 중요한가

모델이 예측하는 실제 값은 absolute velocity가 아니라 다음 step update다. 따라서 output scale도 velocity 전체 분포보다 delta 분포에 맞추는 편이 update prediction에는 더 자연스럽다.

이 변경은 논문 계열 MeshGraphNet의 update 예측 방식과 더 가까운 방향이다.

## 8. acceleration feature 변경

### 8.1 추가된 argument

`--accel-mode`가 추가되었다.

선택지는 두 가지다.

| 값 | 의미 |
| --- | --- |
| `physical` | `(u_t - u_{t-1}) / dt` |
| `delta` | `u_t - u_{t-1}` |

기본값은 기존 호환성을 위해 `physical`이다.

### 8.2 추천 설정

최신 안정성 실험에서는 `--accel-mode delta`를 추천한다.

이유는 `dt=0.01`로 나누면 feature magnitude가 커지고, velocity 정규화와 섞였을 때 학습 scale이 불안정해질 수 있기 때문이다. `delta` mode는 더 부드러운 입력 scale을 준다.

## 9. statistics 계산 방식 변경

### 9.1 기존 문제

기존 stats 계산은 앞쪽 sample 일부에 치우칠 가능성이 있었다. 이러면 전체 trajectory 분포를 대표하지 못할 수 있다.

### 9.2 새 방식

`--stats-sampling`이 추가되었다.

| 값 | 의미 |
| --- | --- |
| `head` | 기존처럼 앞쪽 sample 사용 |
| `uniform` | 전체 train index에서 균등하게 sample 선택 |
| `random` | seed 기반 random sample 선택 |

기본값은 `uniform`이다.

또한 `--stats-samples` 값을 512로 키우는 실행 script를 제공한다.

## 10. physics loss 변경

### 10.1 기존 전제

논문은 continuity, convection, viscosity 항을 사용한다. 하지만 현재 공개 HDF5에는 pressure나 solver 내부 미분 operator가 직접 제공되지 않는다.

따라서 이 구현은 graph neighborhood 기반 finite difference로 유사 항을 구성한다.

### 10.2 새 argument

`--physics-operator`가 추가되었다.

| 값 | 의미 |
| --- | --- |
| `legacy` | 기존 divergence/laplacian 중심 근사 |
| `gradient` | local gradient를 만들고 divergence/convection을 계산 |

`--continuity-target`도 추가되었다.

| 값 | 의미 |
| --- | --- |
| `zero` | predicted divergence가 0에 가깝도록 |
| `match` | predicted divergence가 true divergence와 같도록 |

### 10.3 loss weight 변경 가능

기존에는 data/physics loss 비율이 코드에 고정되어 있었다. 최신 버전에서는 CLI에서 조절한다.

- `--data-loss-weight`
- `--continuity-weight`
- `--convection-weight`
- `--viscosity-weight`

추천 baseline은 다음이다.

```bash
--data-loss-weight 0.5
--continuity-weight 0.1666666667
--convection-weight 0.1666666667
--viscosity-weight 0.1666666667
```

physics가 너무 강해서 rollout이 흔들리면 `run_stability_pi_light.sh`처럼 data loss 비중을 0.7로 높이는 실험을 비교한다.

## 11. 학습 루프 변경

### 11.1 학습 시 prediction 흐름

최신 `train_one_sample(...)` 흐름은 다음과 같다.

```text
1. sample.current_u에 training noise 추가
2. noisy current_u로 node feature 생성
3. model이 normalized delta 예측
4. output_stats로 delta 복원
5. noisy current_u + pred_delta
6. wall/inlet boundary condition 적용
7. learned_node_mask에서 data loss 계산
8. pi model이면 physics loss 추가
```

### 11.2 rollout validation 추가

`--eval-rollout-steps`가 추가되었다. 예를 들어 50으로 두면 매 epoch validation에서 50-step rollout RMSE를 계산한다.

```bash
--eval-rollout-steps 50
```

### 11.3 best checkpoint 선택 기준 변경

`--selection-metric`이 추가되었다.

| 값 | best.pt 기준 |
| --- | --- |
| `one_step` | 1-step validation RMSE |
| `rollout` | rollout validation RMSE |

50-RMSE가 목표라면 다음 조합을 써야 한다.

```bash
--eval-rollout-steps 50
--selection-metric rollout
```

이 변경은 중요하다. 이전에는 1-step이 좋아도 50-step이 나쁜 epoch가 `best.pt`로 저장될 수 있었다. 이제는 목표 metric에 맞춰 checkpoint를 선택할 수 있다.

## 12. evaluation 변경

`scripts/evaluate.py`도 train 쪽 변경에 맞춰 수정되었다.

핵심은 다음과 같다.

1. checkpoint에서 `output_stats`를 읽는다.
2. training 때 사용한 `accel_mode`를 checkpoint args에서 읽는다.
3. prediction 후 `apply_velocity_boundary(...)`를 적용한다.
4. RMSE는 `fluid_node_mask`, 즉 wall을 제외한 영역에서 계산한다.
5. inlet clamp는 기본적으로 켜져 있으며, 필요하면 `--no-clamp-inlet`으로 끌 수 있다.

기본 평가 명령은 다음이다.

```bash
python scripts/evaluate.py \
  --data-dir /home/rintern07/04_npj/coarse_dataset \
  --checkpoint /path/to/best.pt \
  --rollout-steps 50 \
  --device cuda
```

wrapper script를 쓰면 다음처럼 실행한다.

```bash
bash scripts/evaluate_50rmse.sh /path/to/best.pt
```

## 13. TensorBoard 기록

`scripts/train.py`는 `SummaryWriter(log_dir=output_dir)`로 TensorBoard event file을 남긴다.

기록되는 scalar는 다음이다.

| tag | 의미 |
| --- | --- |
| `train/loss` | 학습 loss |
| `train/1-rmse` | training sample 기준 1-step RMSE |
| `eval_1rmse` | validation 1-step RMSE |
| `eval_50rmse` | `--eval-rollout-steps 50`일 때 validation 50-rollout RMSE |

event file은 각 run folder 안의 `events.out.tfevents...` 파일이다.

서버에서 TensorBoard를 실행하는 경우, 로컬 브라우저의 `localhost`와 서버의 `localhost`는 다르다. 서버에서 TensorBoard를 띄운 뒤 로컬 PC에서 보려면 일반적으로 SSH port forwarding이 필요하다.

서버에서:

```bash
tensorboard --logdir runs/in_mgn_delta_rollout --host 127.0.0.1 --port 6006
```

로컬 PC에서:

```bash
ssh -N -L 6006:127.0.0.1:6006 <user>@<server>
```

브라우저:

```text
http://127.0.0.1:6006
```

논문에서도 In-MGN은 long rollout에서 강한 baseline이다. physics loss scale이 아직 완전히 맞지 않으면 data-only가 더 안정적으로 나올 수 있어 비교 가치가 크다.

### 14.4 physics 약하게 비교

```bash
bash scripts/run_stability_pi_light.sh
```

data loss 비중을 0.7로 올리고 physics 총 비중을 0.3으로 낮춘다.

### 14.5 noise sweep

```bash
bash scripts/run_stability_noise_sweep.sh
```

`noise-std`를 0.003, 0.006, 0.01로 비교한다. 목적은 rollout 안정성에 가장 좋은 noise 강도를 찾는 것이다.

## 15. 기존 command에서 바꿔야 하는 argument

기존 command 예시는 다음 구조였다.

```bash
PYTHONPATH=$PWD python scripts/train.py \
  --data-dir 04_npj_GNN/coarse_dataset \
  --output-dir runs/in_pi_mgn \
  --model-variant in-pi-mgn \
  --epochs 20 \
  --message-passing-steps 15 \
  --lr 1e-4 \
  --lr-decay-start-epoch 16 \
  --lr-min 1e-7 \
  --noise-std 0.003 \
  --device cuda
```

최신 안정성 실험에서는 다음 argument를 추가하거나 바꾸는 것을 권장한다.

```bash
--noise-std 0.006
--stats-samples 512
--stats-sampling uniform
--output-scale delta
--accel-mode delta
--physics-operator gradient
--continuity-target zero
--data-loss-weight 0.5
--continuity-weight 0.1666666667
--convection-weight 0.1666666667
--viscosity-weight 0.1666666667
--eval-rollout-steps 50
--selection-metric rollout
--eval-every 1
```

중요한 점:

- `--output-dir`는 실험 이름일 뿐이다.
- 실제 모델 차이는 `args.json`의 `model_variant`, `output_scale`, `accel_mode`, `physics_operator`, `selection_metric`으로 판단해야 한다.
- 같은 `--output-dir`로 두 번 실행하면 같은 폴더에 덮어쓰는 것이 아니라, timestamp 하위 폴더가 새로 생긴다.

## 17. 재현성 주의점

현재 코드는 seed를 설정한다.

- Python `random`
- NumPy
- PyTorch CPU
- PyTorch CUDA

하지만 완전 결정론은 아니다.

특히 다음 연산이 run 간 차이를 만들 수 있다.

- `torch.randperm(...)`
- `torch.randn_like(...)`
- CUDA `index_add_` 기반 graph aggregation
- CUDA `index_add_` 기반 physics operator 누적

따라서 같은 argument, 같은 split, 같은 seed라도 두 run의 validation 결과가 완전히 같지 않을 수 있다. 이 현상은 현재 코드가 checkpoint를 이어 학습해서가 아니라, GPU 학습 비결정성과 loss landscape 차이로 보는 것이 맞다.

추후 재현성 추적을 강화하려면 다음 기능을 추가하는 것이 좋다.

- `run_meta.json`에 실제 command, cwd, hostname, git/hash 또는 file timestamp 저장
- 학습 시작 직후 `init.pt` 저장
- `--deterministic` 옵션 추가
- deterministic mode가 CUDA `index_add_`와 충돌하는지 smoke test

## 18. 아직 논문과 다른 점

이 구현은 논문을 최대한 따라가려는 방향이지만, 다음 차이가 남아 있다.

1. 논문의 정확한 test case 10개 ID가 공개 텍스트에서 명확히 복원되지 않았다.
2. HDF5에 inlet/outlet mask가 직접 제공되지 않아 추론을 사용한다.
3. pressure field와 solver 내부 미분 operator가 없어서 physics loss는 graph finite difference 근사다.
4. 논문의 hidden normalization, loss scaling, batch/rollout training detail은 완전히 알 수 없다.
5. 현재는 rollout loss로 직접 backprop하는 구조가 아니라, rollout validation으로 best checkpoint를 고르는 구조다.

## 19. 현재 수정안에서 기대하는 효과

기대하는 효과는 다음과 같다.

| 변경 | 기대 효과 |
| --- | --- |
| geometry-first inlet/outlet | 잘못된 inlet clamp 감소 |
| wall/inlet boundary helper 통일 | train/eval mismatch 감소 |
| position feature 추가 | geometry-dependent flow 예측력 증가 |
| delta output scale | update prediction scale 안정화 |
| delta acceleration | feature magnitude 안정화 |
| uniform stats sampling | normalization 편향 감소 |
| rollout checkpoint selection | 실제 목표 metric에 맞는 best.pt 선택 |
| training noise 개선 | rollout 중 off-manifold state 회복력 증가 |

## 20. 다음으로 가장 가치 있는 개선 후보

현재 50-RMSE가 약 40까지 줄었다면, 다음 개선은 아래 순서가 가장 합리적이다.

1. **run metadata 저장**

   같은 argument run 비교가 계속 헷갈릴 수 있으므로, `run_meta.json`과 `init.pt` 저장을 먼저 넣는 것이 좋다.

2. **inlet/outlet mask 검증**

   `inspect_boundaries.py` 결과를 여러 case에서 확인하고, cap 분리가 실패하는 case가 있는지 찾아야 한다.

3. **data-only In-MGN과 In-PI-MGN 비교**

   physics loss가 아직 논문 scale과 맞지 않으면 In-MGN이 더 좋을 수 있다.

4. **noise sweep**

   현재 0.006을 추천하지만, 0.003/0.006/0.01 중 실제 50-RMSE가 가장 낮은 값을 확인해야 한다.

5. **deterministic audit**

   같은 argument로 두 run이 얼마나 흔들리는지 정량화해야 한다.

6. **rollout-aware training**

   현재는 rollout으로 best checkpoint만 고른다. 다음 단계에서는 짧은 rollout loss를 training에 일부 넣는 방식을 검토할 수 있다. 다만 이건 코드 복잡도가 커지므로, 지금보다 한 단계 뒤에 하는 것이 좋다.

## 21. 추천 결론

현재 최신 수정안의 핵심은 **논문 구조를 보수적으로 유지하면서 rollout 안정성에 직접 영향이 큰 부분을 정리한 것**이다.

가장 먼저 돌릴 실험은 다음이다.

```bash
bash scripts/run_stability_delta_rollout.sh
```

그 다음 비교할 실험은 다음이다.

```bash
bash scripts/run_stability_in_mgn_data.sh
bash scripts/run_stability_pi_light.sh
bash scripts/run_stability_noise_sweep.sh
```

평가는 항상 각 run의 `best.pt`에 대해 다음으로 통일한다.

```bash
bash scripts/evaluate_50rmse.sh /path/to/best.pt
```

그리고 같은 argument로 다른 결과가 나오는 문제는 현재 구조에서 충분히 가능한 현상이므로, 이어 학습 여부를 의심하기보다는 **run metadata와 deterministic audit을 추가해서 실험 신뢰도를 높이는 방향**이 다음 단계로 가장 중요하다.
